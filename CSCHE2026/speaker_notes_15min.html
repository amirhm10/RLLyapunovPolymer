3

Linear MPC Is Practical, But Its Model Is Local

0:55-1:45

Read aloud

Linear MPC is a very strong baseline for process control. It handles multivariable interactions, constraints, and receding-horizon optimization in a form that is familiar for implementation. Offset-free augmentation also helps reject steady disturbances. The limitation is that the linear model is identified locally. Near the nominal point it predicts well, but as the process moves away from that region, mismatch can grow and tracking can degrade. This is the opening for learning-based adaptation.

Point to figure: nominal region, nonlinear plant curve, linear model line, and mismatch away from nominal operation.

Transition: "RL can help with this mismatch, but direct online exploration creates a different problem."

4

RL Can Adapt, But Online Exploration Is Risky

1:45-2:25

Read aloud

Reinforcement learning is attractive because it can learn from process data and adapt to nonlinear behavior or model mismatch. But in process control, exploration is not free. A bad action is not just a bad sample; it can violate input or output constraints, create unsafe operating conditions, or damage product quality. So the question is not only how to learn a better policy. The key question is how to keep final actuation safe while the policy is learning.

Emphasize: "bad action is not just a bad sample." This is a good line for the audience.

5

Imitation-Learning Pretraining Warm-Starts the RL Actor

2:25-3:15

Read aloud

The first step is to avoid starting the RL actor from a random policy. We use offset-free MPC as an expert controller offline. From those trajectories, we collect transition tuples containing the state, the MPC action, the reward, and the next state. Then we train the actor with a Huber behavior-cloning loss so that the policy initially imitates the MPC action. This does not replace online learning. It simply gives the actor a practical starting point before interacting with the nonlinear plant.

Say "state includes the estimate, setpoint, and previous input." Keep the math quick unless asked.

Transition: "However, a good initial policy is still not a safety certificate."

6

Pretraining Gives a Good Start, But Online Safety Is Still Uncertified

3:15-3:55

Read aloud

Pretraining reduces random early exploration and starts the actor close to a controller we already understand. But after online updates, the actor can drift. It can encounter states that were not well represented in the offline data. At that point, tracking may be good, but the action is still not certified for Lyapunov decrease or constraint-compatible actuation. This is why pretraining alone is not enough for the safety story.

Avoid saying "pretraining guarantees safety." It does not. It improves initialization and tracking behavior.

7

RL Proposes the Move; the Lyapunov Layer Has Final Authority

3:55-4:45

Read aloud

This slide is the core architecture. The RL actor proposes a candidate control move. But that candidate is not sent directly to the plant. First, the Lyapunov gate checks whether it satisfies the contraction condition relative to a local target. If the action passes, it is applied. If it fails, the fallback Lyapunov MPC computes a replacement action. So the plant receives either an accepted learned action or a certified fallback move. In other words, RL is a proposal generator, and the safety layer has final authority.

Presenter cue: slow down here. This is the main concept of the talk.

8

Safety Check: One-Step Lyapunov Contraction

4:45-5:35

Read aloud

The safety check is a one-step Lyapunov contraction test. We compute the error between the current state estimate and the local target, and define a quadratic Lyapunov function V. Then we predict the next state under the candidate action. The gate accepts the action only if the predicted next Lyapunov value is less than a contracted version of the current value, with a small tolerance. Visually, accepted actions move the state toward a lower Lyapunov contour. Failed actions are replaced.

Use the phrase: "This is a runtime certificate, not a reward term."

9

Rejected RL Actions Are Replaced by a Lyapunov MPC Move

5:35-6:25

Read aloud

When the candidate action fails the gate, the fallback controller solves a compact tracking problem. It balances tracking and input movement, respects the direct input bounds u_min ≤ u ≤ u_max, and enforces the same Lyapunov contraction inequality. The target selector provides a feasible local equilibrium, and the fallback LMPC computes an action that pulls the predicted state back toward that target. This is how we keep the final action supervised even when the learned policy proposes something risky.

Important notation: say "direct input bounds," not "delta u bounds."

10

Reward Converts Tracking and Safety Feedback Into Learning

6:25-7:05

Read aloud

The reward is designed to push the actor in two directions at the same time. First, it should improve tracking and avoid aggressive input movement. Second, it should learn actions that require fewer safety corrections. That means the policy is not only optimized for the tracking objective; it also receives feedback from the supervision layer. Over training, the actor should become more compatible with the Lyapunov gate.

Transition: "To learn from the important rare events, we also need the replay buffer to sample intelligently."

11

Replay Sampling Balances Rare Failures, Recent Data, and Coverage

7:05-7:45

Read aloud

The online replay strategy mixes three views of the data. Prioritized replay revisits rare or high-error transitions. Recent replay keeps the update connected to the current operating regime. Uniform replay preserves broad coverage of the buffer. This is useful because safety-relevant events may be rare, but they are exactly the events the actor should learn from.

If time is tight, give only the three replay views and move on.

12

Online Procedure: Observe, Propose, Certify, Learn

7:45-8:30

Read aloud

Putting the pieces together, each sampling time follows the same loop. We estimate the state and disturbance, propose an RL action, compute the local target, check the Lyapunov condition, execute either the accepted RL action or fallback LMPC action, and then store the transition for TD3 updates. During the early behavior-cloning window, the actor is softly kept close to LMPC while the replay buffer fills. The main point is that certification happens before actuation, and learning happens after the executed transition is observed.

The Lyapunov Gate Enforces a Runtime Certificate

Read aloud

This slide is the main safety result. The top plot compares the contraction-test failure rate for the gated runs and the no-gate diagnostic run. With the gate active, the applied actions have failure rates close to zero, around 0.10 percent. 20

Conclusions and Future Work

13:50-15:00

Read aloud

To conclude, the main contribution is a supervised RL control architecture where the learned actor proposes actions, but a Lyapunov gate certifies or replaces them before actuation. The certificate is practical and local: it uses step-test data and a linear state-space model. In the polymer CSTR case study, pretraining improves tracking, and the LMPC fallback preserves safe actuation when the learned action is not certified. For future work, we want to pretrain the agents using LMPC demonstrations instead of offset-free MPC, scale the method to a C2-splitter distillation column with output constraints and flooding or fault prevention, and complete the stability proof. Thank you, and I would be happy to take questions.

Final emphasis: "RL proposes, Lyapunov certifies, LMPC backs up."
